Guide

Using this site

A short walkthrough of the Blog and the XSS Lab attached to it, from browsing a normal post to reading an Auditor finding.

1. Explore the Blog

Open the Blog home page and browse the three seeded posts. Open one of them and try its comments and search — this is normal, safe-by-default behavior. The Blog is the application the XSS Lab analyzes.

Open Blog →

2. Open the XSS Lab

The XSS Lab contains controlled vulnerable and secure variants of real Blog features: the same post, the same comments, and the same search, each rendered two different ways.

Open XSS Lab →

3. Stored XSS

Open the vulnerable variant of the demo post and submit a comment. Name and Email can be any harmless placeholder text; put <script>alert(1)</script> in Content. The comment is saved as a real row in the Blog's Comment table. Reload the vulnerable page and the script runs again for anyone who opens it. Open the secure variant of the same post: the same stored comment is now displayed as plain text instead of executing.

Open Stored XSS (vulnerable) → Open Stored XSS (secure) →

4. Reflected XSS

On the vulnerable search variant, enter <script>alert(1)</script> and observe the search term reflected straight back into the page as a running script. On the secure search variant, repeat the same query and confirm it is shown as escaped text instead.

Open Reflected XSS (vulnerable) → Open Reflected XSS (secure) →

5. DOM XSS

On the vulnerable preview, type <img src=x onerror=alert(1)> and observe the client-side preview execute it via innerHTML. On the secure preview, enter the same value and confirm it appears as plain text via textContent instead.

Open DOM XSS (vulnerable) → Open DOM XSS (secure) →

6. Auditor

Open the Auditor and click "Scan project". Each row in the results reports a rule (the detected unsafe pattern), a severity (its review priority), the file and line where the pattern occurs, and a short snippet of the matching code. The Auditor performs static source analysis only: it never runs the application, and every finding requires human review before you treat it as a real vulnerability.

Open Auditor →

7. Finish

You have seen the Blog behave safely by default, each vulnerability demonstrated and fixed on real Blog data, and the Auditor find the same patterns in the project's source.

Blog → XSS Lab → Auditor →
